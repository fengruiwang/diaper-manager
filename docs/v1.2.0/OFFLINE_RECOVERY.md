# v1.2.0 云服务故障下的本地运行与恢复合同

状态：已纳入开发要求；本文件是设计合同，不表示已完成端到端实现。

## 不可突破的约束

- CloudBase 停机、欠费、到期、HTTP 超时、429/5xx、跨域异常或网络断开后，已经安装并缓存静态资源的 PWA 仍可在原手机中打开、查看并录入本地数据。
- 原数据键 xiaobao_diaper_planner_v1 永久保留。保留仅本地使用模式；未登录或未加入家庭的原有用户不应因联网功能而被阻断。
- 只要本机持久存储仍在，CloudBase 无法连接也不能自动清空库存、采购记录、体重或价格；不能把本地保存显示成云端成功。
- 浏览器数据被用户清除、设备丢失或卸载应用可能导致本地数据丢失，因此仍需 JSON 备份；首次访问或新设备在无网时不能保证打开。
- 云服务恢复之后先核对家庭身份与服务端变更，再补传本机未确认的操作，最后校验结果。不能上传整个陈旧 state 覆盖云端。

## 状态机

| 状态 | 行为 |
| --- | --- |
| local-only | 用户不启用家庭同步，本地功能完全正常 |
| synced | 云端校验成功且待处理队列已清空 |
| degraded | 断网/服务端失败，本机继续操作并保留待同步队列 |
| auth-required | 令牌失效，暂停云端写入、继续本地记录，重新认证后恢复 |
| recovering | 联网后拉取服务端修订及变更，逐条补传 |
| conflict | 绝对库存盘点/同一条记录并发编辑冲突，保留原操作等待确认 |
| permission-denied | 成员权限已被撤销，停止向该家庭上传；本地旧缓存不能被远程抹除 |

## 写入与队列

- 每个更改记录生成稳定 operation_id；超时重试、应用重开、离线恢复均不生成新的 ID。
- 首选 IndexedDB 存储本地权威快照、待传 outbox、云端游标与版本；保证单事务提交，或操作日志先落盘再可重放构建页面状态。
- 旧 localStorage 作为兼容缓存和备份依据，不能误以为 localStorage 与 IndexedDB 跨库写入具有原子性。
- 只在收到服务端 ACK 或同 ID 已执行的可信回执，并将该回执持久化后，标记操作已同步。
- 服务端事务必须按 family + operation_id 去重，同时核对 payload 哈希，不能让相同 ID 换数据。
- 采购/消耗使用独立相对事件，服务端核验库存非负及业务权限；绝对盘点采用 expected_revision，遇到冲突必须提示用户，不能擅自覆盖。
- 体重和设置的更新/删除使用固定记录 ID、revision、tombstone；本机要立即重算体重推荐尺码。
- 家庭 A 本地队列绝不能在切到家庭 B 的账号后被上传；每个本地账户/家庭的存储必须隔离。

## 服务恢复流程

1. 校验登录、家庭成员资格和应用访问许可。401 提示重新登录，403 阻止向家庭继续上传，网络/5xx 则进入 degraded。
2. 拉取云端自上次游标以来的变更；游标过旧时恢复完整快照和修订版本。不能仅靠 Realtime 推送。
3. 根据服务端修订调整待同步操作：追加型事件交给事务处理；库存盘点和相同实体编辑比较版本，冲突必须单独处理。
4. 使用原 operation_id 依次补传；ACK 丢失时同 ID 重试，禁止重复入库。
5. 在校验各尺码库存、交易记录集合、体重/参考价后展示已同步；网络失败或数据不一致仍展示待同步或冲突。
6. 前台打开、恢复网络或从后台切回时触发同步，前台可低频轮询；不保证在后台或关机时即时推送。

## 双设备特殊情况

- 两人断网各录入一包 S 码，恢复后必须记两条购买流水、正确累加。
- 两人断网都对 S 码执行绝对盘点，不能让后到达的旧数量覆盖先提交的数据。
- 两人离线消耗导致实际库存不足，服务端拒绝不合法事件并保留冲突供人处理，不能默默丢失消耗记录。
- 一人删除最新体重、另一人编辑旧体重时，必须按实体 ID/修订处理，不能复活被删除记录。
- 失效账号不能无提示再上传；离线缓存也不能被当作长期有效的云端授权。

## 集成验收闸门

1. 人为阻断 CloudBase，仍能录入、关闭 App、重开后查看数据和等待同步数。
2. 离线 50 次跨采购/消耗/体重操作、反复重启后队列不丢、不重。
3. 服务端已提交但 ACK 丢失，重试不多加库存。
4. 双手机同时离线后再联网，追加型事件全部保留、盘点类冲突显式处理。
5. 401/403/429/5xx/断网/服务到期均不清空本机真实记录，不显示已同步。
6. 套餐恢复后可以安全增量补传；若云端数据已被平台删除，则停止自动合并，提示重新建库并审核恢复方案。
7. 全部旧版 JSON 兼容、GitHub Pages / Edge PWA 原位更新，绝不强制卸载重装。

注意：以上是产品合同和后续测试要求。CloudBase PostgreSQL SDK 当前不能在前端直接进行多步事务，应由鉴权的服务端 RPC 完成原子写入。
