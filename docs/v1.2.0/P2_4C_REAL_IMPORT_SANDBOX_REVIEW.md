# 小宝管家 v1.2.0 — P2-4C 正式旧版导入器的隔离实际执行验收

更新：2026-11-11。**仅在 GitHub Actions 一次性 Node.js VM 内，用合成数据执行现有正式 v1.1.2 导入/保存/读取函数；从未在用户手机执行真实覆盖恢复，也没有操作 CloudBase。**

## 本次真实代码执行边界

- `tests/helpers/isolated-v1-import-harness.cjs` 从仓库**当前正式 `index.html`** 逐行提取 `importData(file)`、`load()`、`save()`、`defaults()`、`num()`、`clamp()`、`SIZES` 和 `KEY` 的**原样源代码**。这些函数的实现逻辑没有被测试系统重写。
- 在 `vm.createContext` 的一次性 Node.js 内存沙箱里执行上述函数。仅提供合成 `FileReader`、显式确认回调，以及**沙箱自己的** `localStorage` Map。沙箱 `clear/removeItem` 均会抛错，无浏览器真实存储/网络/用户文件路径，也不读真实备份 JSON。
- 使用仓库当前 `growth.js` 的真实 `XBGrowth.extras/syncAutoSize` 进行资料/体重逻辑处理。沙箱里的正式 `save()` 将状态写进仅该次运行可见的 Map；随后通过真正的 `load()` 读取该 Map，相当于在模拟页面重启后再次载入。
- `tests/legacy-real-import-isolation.test.cjs` 新增 **12 项合成验收**，涵盖完整历史恢复、拒绝替换确认、错误 JSON 格式、库存数量四舍五入、目标/日用量上限修正、购买/比价/参考价精度、未知嵌套字段丢失、超范围体重记录过滤、默认字段填补、备份版本不检验，以及 P2-4B 独立投影与真实函数结果的对照。

## 已明确确认的现有 v1.1.2 导入行为

| 样本/场景 | 隔离实际导入结果 | 迁移设计影响 |
|---|---|---|
| 完整且各字段符合旧版规范的合成备份 | `importData` 写入沙箱 Map，`load` 重新读取后逐字段一致 | 规范备份可作为升级映射基础；并非用户真实备份已恢复 |
| 只取消导入确认 | 不写沙箱 Map | 用户取消不应改变正式数据 |
| 数据缺失默认字段 | 自动补入旧版默认值 | 必须显示差异，不可无条件标记“字节级无损” |
| 非整数库存、负值或超出范围 | 自动四舍五入/限制 | 库存修订应进入显式冲突/修正流程，不可静默写入云端 |
| 完整采购、比价、参考价覆盖数据 | 测试样本中保持一致，包括三位小数参考价 | 未来需逐记录核对、货币表示与历史金额合计 |
| `babyProfile`、`weightRecords` 中的未知扩展字段 | 旧版 `XBGrowth.extras` 可能去掉字段 | 新迁移必须先原样备份，保留未知字段或把它列为阻断 |
| 超出旧版规则的体重记录 | 旧导入器会过滤 | 不能无提示删除历史 |
| 备份版本 `version=2`（其他字段仿真合法） | 旧导入器**仍接受**，因其并未检查版本号 | 新升级预检必须明确限制 `app/version` 并拒绝未知版本 |
| 独立 P2-4B 投影 | 多组标准和异常样本与实际 `importData` 写入状态一致 | 已为“真实导入前先预览差异”建立模拟可信度 |

测试会返回差异类别、数量等安全信息，不输出任何真实人的姓名、消费细目、购买 ID 或家庭标识。全部案例只用代码内构造的合成样本。
