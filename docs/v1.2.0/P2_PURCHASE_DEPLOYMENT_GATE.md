## 安全部署顺序（需先完成 SQL 与权限审查）

1. 011：真实 CloudBase **只读**部署前检查，预计 **11/11 true**；任何 false 先停止评估。
2. 001：现有共享家庭基础架构（已在线上安装；不用重复执行）。
3. 005：首次创建空的宝宝、体重、库存及迁移表（需事先明确授权）。
4. 006：只读静态/空表检查。
5. 008：创建采购流水表及 RLS（需授权）。
6. 009：创建**唯一**安全库存 RPC，要求 kind=buy 一并提交完整采购详情（需授权）。
7. 010：安装库存快照/本人回执一致性只读 RPC（需授权）。
8. 012：首次部署后 **12 项只读检查**，在创建任何虚拟宝宝和数据前运行。

**不得部署 007 临时版本。** 009 已包含 007 的库存事务、去重索引、撤销约束逻辑，并使用 DROP FUNCTION IF EXISTS 清理可能存在的旧 9 参数接口。这样不会在正式环境暴露“只增加库存、不写采购流水”的临时 RPC。

## 安全/兼容

- 所有写入通过同一个 SECURITY DEFINER RPC，函数体检查 auth.uid、auth.role、xb 应用许可。客户端不获得 xb_transactions 直接写权限。
- 必须提交 brand、series、total_fen、purchase_date，所有信息参与服务器摘要。不能同一 ID 重试不同价格。
- 采购、库存更新、事件回执在一次数据库事务内；撤销保留原始流水和取消关联。
- 旧版原始 price 可能为浮点数，迁移时必须先通过精度检查，超过两位小数需人工核实，不能直接截断。
- 在隔离的 PostgreSQL CI 环境使用虚拟家庭数据验证语法、身份/RLS、错误及原子性。CI 通过不代表腾讯云真实联调通过。
- 此版本不创建真实宝宝、不上传历史记录、不修改 v1.1.2 本机数据。
