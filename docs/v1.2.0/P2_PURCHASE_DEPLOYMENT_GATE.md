# P2 采购与库存安全部署闸门

状态：008 与 009 为开发草案，尚未部署腾讯云，也未上传家庭原始采购数据。

未来审查顺序：005 基础业务表 → 006 只读检查 → 007 临时库存 RPC → 008 采购流水表 → 009 替换 007 的 9 参数旧 RPC 为 10 参数采购安全版本。**007 不能单独对真实家庭开放**。正式部署前应整合到受控的单事务迁移，避免旧接口暴露窗口。

009 的 p_purchase (jsonb) 必须完整包含 brand、series、total_fen、purchase_date，其他业务操作传 SQL NULL。品牌、系列、人民币分和购买日期都参与服务器固定摘要。同一 operation_id 的重试修改价格或品牌应被拒绝，而非重复入库。撤销购买会写反向事件并标记原采购被撤销，采购及库存同事务提交。

必须有真实 PostgreSQL 的权限负面测试、并发、超时幂等、事务回滚和迁移兼容验证之后才能开放给两台手机；目前 Node 模拟与 SQL 静态检查不能代替这些验收。

正式 v1.1.2 的历史 localStorage 不被读取和覆盖；用户需显式确认才可迁移。
