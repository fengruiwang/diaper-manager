# v1.2.0 历史数据迁移只读预检

状态：开发分支代码和测试；**尚未接入正式 PWA、尚未在云端执行迁移**。

\`sync/legacy-migration-manifest.js\` 组合原有 \`migration-contract.js\` 的原样 SHA-256 摘要、\`legacy-purchase-audit.js\` 的金额精度验证，另外检查采购、候选报价、宝宝体重、自定义参考价、未来未知字段。

## 关键保真原则

1. \`state.inventory\` 的 6 个尺码库存是**当前数量的唯一初始基准**。旧版本支持直接盘点和撤销，不可把历史 \`state.transactions\` 再次累计到当前库存。
2. 旧采购金额 \`transactions[].price\` 应无损换算整数人民币分；若存在三位小数则阻止自动迁移、需人工核对，不能静默舍入。
3. 自定义参考价 \`referenceOverrides\` 的单位是元/片，可有三位小数；**不得误按整笔采购金额只能保留两位小数的规则处理**。
4. 报价 \`quotes\` 存储包片数/包数/片数/实付金额及算出的单片价；不能将 \`unit\` 当作独立需要相加的总金额。
5. 单条体重是按输入日期/时间和 kg 存储，保存三位小数；宝宝出生体重属于档案，不重复生成一条测量记录。
6. 已知的 18 个顶级字段均指定未来目标模块。未知字段或旧记录附带的自定义字段必须显示为 \`unmapped_field\` 并暂停自动云端迁移，**原始备份必须保留全部字段**。
7. \`readOnlyPreflightPass=true\` 只表示当前只读核对未发现阻断项，\`canUpload\` 在本阶段始终是 \`false\`，需要完整业务表、幂等迁移 RPC、原机备份及用户确认后才能改变。
8. 验证结果只输出摘要、路径、错误码和哈希，不把宝宝信息、采购详情或邮箱发到公共 GitHub。
