# 小宝管家 v1.2.0 — P2-4B 独立恢复投影差异审查

日期：2026-11-11。状态：**开发分支合成历史记录测试 10/10 PASS，完整 JS 回归 326/326 PASS；没有在真实使用中的浏览器执行导入、替换 localStorage 或腾讯云迁移**。

## 为什么需要这个阶段

P2-4A 用户真实浏览器核验已经通过：原始 v1.1.2 备份可以被完整封存和取回，截图显示保护副本二次核验 PASS、原始长度 3265 字节。但这只能证明备份文件本身可恢复，**不能证明现行 v1.1.2 `importData()` 导入后的状态与原 JSON 逐字段一致**。

正式 `index.html` 的 `importData` 会执行：
- `defaults()` 与原始字段合并，可能补上缺少的字段；
- `inventory/target/daily` 六尺码数值转换、四舍五入及上下限钳制；
- `XBGrowth.extras()` 规范化 `babyProfile`、`weightRecords`、`sizeMode`、`autoSize` 和补货策略，可能删除嵌套扩展字段、过滤不合法体重记录；
- `XBGrowth.syncAutoSize()` 计算后返回，但不主动改变旧库存；
- 最终会调用 `save()` 将新状态写进 `localStorage`，所以**绝不能用正在使用的正式手机作导入一致性试验**。

## 本次交付

- `sync/legacy-restore-projection.js`：纯 JavaScript，在内存中对 **已导出 JSON 文件数据对象**模拟上述导入后投影，并比较原始 `data` 与模拟状态的逐字段差异。
- `tests/legacy-restore-projection.test.cjs`：10 项合成测试，包括完整老版数据投影一致、缺字段补默认、库存四舍五入/超限修正、未知宝宝/体重字段受损、非法体重过滤、价格参考 3 位小数保持、无原始历史输出、现有正式导入源码关键规则对照以及无存储/网络写入。
- 当前累计 `326/326` 项 JavaScript PASS；原 PostgreSQL 隔离合同 PASS。

## 风险分类

- `PROJECTION_IDENTICAL`：模拟旧版导入状态与原导出 `data` 的全部字段和值一致。**仅模拟一致，不等于真实网页上的正式导入恢复已经成功**。
- `PROJECTION_DIFF_REVIEW_REQUIRED`：至少一个字段存在删除、增加或数值变化。即使仅是补充默认值，也不能直接宣称无损恢复。
- 报告只输出数据类别（库存、采购、比价、体重、参考价等）与差异数量，不输出品牌、历史金额、宝宝姓名、备注、UID、原始记录 ID 或敏感的未知字段名。
- 报告的 `canReplaceLocalState:false` / `canUpload:false` / `productionImportExecuted:false` 永远为真（禁止向用户声称导入或迁移已发生）。

## 当前缺口

1. 只是**对照真实正式源码实现的独立内存模拟**，没有驱动完整原始 UI 的真正 `importData()`，后续还需在新建隔离浏览器或一次性测试站点中验证由真实导入器写入后的完整内容。
2. 需要逐字段规定允许的规范化（例如旧记录缺失的默认属性）和**绝不允许**丢失/变更的敏感业务信息（库存、采购、单片价、目标价、体重历史）；不能把所有不同都静默归一化。
3. 数据备份可恢复和迁移授权是两个独立闸门；既没有真实后端迁移收据，也没有 CloudBase 真实业务写入权限。
4. 用户现在无须重新导出、上传自己的 JSON、在正式版点击导入或重复跑 P2-4A。下次如需手动验收，仍要在对话里直接提供**完整测试代码文件、上传目标、操作步骤、预期和异常反馈方式**。

## 本轮数据保护界限

开发全部在 `feature/cloudbase-sync-v1.2.0`。未修改 `main`、旧版 PWA、用户原 `localStorage['xiaobao_diaper_planner_v1']`、云端家庭/成员、虚拟测试宝宝或采购库存记录。任何真实数据库写入及正式发布仍需单独明确授权。
