# 小宝管家 v1.2.0 — P2-4E-B1 旧版完整备份的原子归档（仅隔离测试）

日期：2026-11-11。**本阶段是归档暂存，不是正式数据迁移成功。SQL 022 仅在一次性 PostgreSQL 16 CI 执行，从未安装到真实 xiaobao-family。**

## 本轮成果

新增 [022 原子归档 SQL 草案](../../cloudbase/sql/022_xb_legacy_archive_atomic_STAGE_DRAFT_DO_NOT_DEPLOY.sql)。该文件建立两张**私有**归档表：

- xb_legacy_staging：按原始 UTF-8 文本保存完整 v1 备份，记录由服务器计算的 SHA-256、字节长度、完整状态 JSONB、计数、家庭和宝宝范围。
- xb_legacy_stage_records：按原始 ID 和顺序保存每笔采购/消耗、比价、成长记录的 JSONB 对象。参考价、目标/日用量、宝宝资料和全部设置同时保留在原始备份与状态快照中。

草案 RPC xb_stage_legacy_archive_draft 仅接受已登录家庭 owner 及 xb 授权，且宝宝必须是未停用的 primary。验证外层版本与日期、六尺码整数库存、采购总价精确到分、参考价最多 0.001 元精度、成长记录、未知字段及重复 JSON 键。它对同一份内容计算服务器 SHA-256，并通过家庭级事务锁和唯一约束处理重复提交。

**本阶段不写 xb_inventory、xb_inventory_operations、xb_transactions 或 xb_migrations**，所以旧采购不会重复增加现存库存，也不会凭归档成功伪造迁移完成证明。所有返回都固定 can_upload=false、can_commit=false、receipt_committed=false。

现有 xb_transactions 依赖实时库存事件外键；如果直接把旧购买作为普通 buy RPC 回放，会重复计入库存，因此必须把历史账本归档和新库存基线初始化区分开。

## 隔离测试结果

- [原子归档合同](../../tests/postgres/p2_legacy_archive_atomic_contract.sql)：实际 PG16 合成数据通过；归档 2 条交易、1 条比价、1 条体重，保存完整原始 JSON 和服务器哈希。模拟晚到的报价记录写入失败后，归档主行与已写历史行一起回滚。
- 严格拒绝不合法 JSON 版本、采购金额第三位小数、库存小数、必要字段 JSON null、重复 JSON 键、无权限成员及匿名访问；归档明细表不给普通客户端直接读取权限。
- [真实两个数据库连接并发脚本](../../tests/postgres/p2_legacy_archive_concurrency.sh)：两个事务提交同一份合成备份，最终 **一次首次归档成功、另一次安全识别为重复**，四条历史明细保留，实时库存/交易/完成收据均为零。
- GitHub CI：**JavaScript 364/364 PASS**；PostgreSQL 主合同、原子回滚及真实双连接竞争均 PASS。
